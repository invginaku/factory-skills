# Issue tracker: Яндекс Трекер

Задачи этого репозитория живут в Яндекс Трекере. Все операции — через REST API `https://api.tracker.yandex.net/v2` (`curl` + `jq`). Всё, что публикуется в Трекер (комментарии, описания, тикеты), пишется **по-русски**.

## Аутентификация

Заголовки каждого запроса:

- `Authorization: OAuth $TRACKER_TOKEN`
- Для организаций Яндекс 360 — `X-Org-ID: $TRACKER_ORG_ID`; для Yandex Cloud — `X-Cloud-Org-ID: $TRACKER_CLOUD_ORG_ID` (задан ровно один из них)
- `Content-Type: application/json`

Очередь по умолчанию — `$TRACKER_QUEUE` (например `PILOT`). Ключи задач имеют вид `QUEUE-123`.

## Конвенции

- **Создать задачу**: `POST /v2/issues/` с телом `{"summary": "...", "queue": "$TRACKER_QUEUE", "description": "..."}`. Ответ содержит `key`.
- **Прочитать задачу**: `GET /v2/issues/<key>`, комментарии — `GET /v2/issues/<key>/comments`.
- **Найти задачи**: `POST /v2/issues/_search` с телом `{"filter": {"queue": "$TRACKER_QUEUE", "tags": "...", "resolution": "empty()"}}`; для сложных выборок — `{"query": "Queue: PILOT Tags: \"ready-for-agent\" Resolution: empty()"}` (язык запросов Трекера).
- **Комментировать**: `POST /v2/issues/<key>/comments` с телом `{"text": "..."}`. Разметка — YFM (Яндекс-flavored Markdown).
- **Метки**: в Трекере это теги. Добавить/снять: `PATCH /v2/issues/<key>` с телом `{"tags": {"add": ["..."], "remove": ["..."]}}`.
- **Закрыть**: статусы меняются переходами воркфлоу, а не полем. Список доступных: `GET /v2/issues/<key>/transitions`; выполнить: `POST /v2/issues/<key>/transitions/<id>/_execute` (при необходимости с `{"resolution": "fixed"}`). Не угадывай id перехода — сначала запроси список.
- **Назначить исполнителя**: `PATCH /v2/issues/<key>` с телом `{"assignee": "<login>"}`; свой логин — `GET /v2/myself`.

Конвенции агентских тегов (совместимы с конвейером фабрики): `ai:прожарить` — запрос прожарки, `ai:прожарено` — прожарка выполнена, `ai:ошибка` — сбой автоматики. Комментарии автоматики начинаются с маркера `🤖`.

## Когда скилл говорит «publish to the issue tracker»

Создай задачу в Яндекс Трекере (`POST /v2/issues/`) в очереди `$TRACKER_QUEUE`.

## Когда скилл говорит «fetch the relevant ticket»

`GET /v2/issues/<key>` плюс `GET /v2/issues/<key>/comments`.

## Wayfinding-операции

Используются `/wayfinder`. **Карта** — одна задача, тикеты — её подзадачи.

- **Карта**: задача с тегом `wayfinder:map`, тело — Notes / Decisions-so-far / Fog.
- **Дочерний тикет**: подзадача карты — при создании передай `{"parent": "<ключ карты>"}`. Теги: `wayfinder:<type>` (`research`/`prototype`/`grilling`/`task`). После взятия в работу тикет назначается на ведущего.
- **Блокировки**: нативные связи Трекера. Добавить: `POST /v2/issues/<key>/links` с телом `{"relationship": "depends on", "issue": "<ключ блокера>"}`. Прочитать: `GET /v2/issues/<key>/links` — тикет разблокирован, когда все связи `depends on` ведут на закрытые задачи.
- **Запрос фронтира**: открытые подзадачи карты (`POST /v2/issues/_search` с `{"filter": {"parent": "<ключ карты>", "resolution": "empty()"}}`), отбросить те, у кого есть открытый блокер или назначенный исполнитель; первая в порядке карты побеждает.
- **Занять тикет**: назначить себя исполнителем — первая запись сессии.
- **Закрыть вопрос**: комментарий с ответом, затем переход в закрытый статус, затем дописать указатель на контекст в Decisions-so-far карты.
